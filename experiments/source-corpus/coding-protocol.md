## Scope and sampling

This protocol is fixed before either coder creates effect labels. The frame, exclusions, source pins and duplicate clusters are already frozen. Code all 39 selected distinct Pipeline bodies; report their repository and shared-family structure. They are a convenience source corpus, not 39 independent deployments or randomly sampled failure incidents. All 391 Task and 425 StepAction references have source snapshots; runtime images and opaque helper behavior are not resolved by that fact.

Two separately instructed automated agents code the same frozen packet without seeing each other's labels or manuscript policies. They are automated source coders, not human participants. Their common system provenance and nonindependence from the project must be disclosed. Source citations and adjudication, rather than agreement alone, support each accepted finding.

## Coding

For each composition, supply a coverage record containing every ordinary/finally Task name, inspected files and unresolved helper/runtime boundaries. Create effect/precondition records using CODING_SCHEMA.json. Record explicit reads, writes, availability/identity conditions, initialization, destructive cleanup, external API/registry/cloud/Kubernetes state and optional branches. Cite exact frozen source file, line range and quotation. Do not infer an effect solely from a task name or an opaque script invocation.

Where source supports an across-task relationship, record both producer and consumer evidence and a conditional reuse obligation: state identity, binding/branch assumptions, trigger that makes old state unusable, and any source-supported repair candidate. Distinguish necessary precondition from complete valid repair. With no actual run/state record, the trigger is a source-derived hypothetical, not a historical failure. Unknown cases remain visible; no forced positive or full repair set is required.

Classify confidence as Source-explicit, Interface-supported or Unknown. Classify the relationship's structural visibility separately: explicit task-result reference, common Workspace binding, ordering only, external state without either, or Unknown. This is dependency-specific visibility; it does not mean an actual plan has zero warnings. A concrete zero-warning statement requires a separately retained executable planner input/output, not static guessing.

For supported repair candidates, classify whether the producer is earlier/parallel to the consumer, whether it is a later descendant, or Unknown. This concerns the current policy's expressibility and must not be inferred from lexical YAML order. Note finally-phase cleanup and intra-Task initialization that whole-Task retry already repeats. Those can be negative findings rather than extra-task dependencies.

## Analysis fixed before labels

Publish each original coder's files before adjudication. Report composition-level counts with denominators for inspected, source-supported and Unknown; summarize effect classes, structural visibility and backward-policy expressibility. Also report repository/family counts so related release-service compositions cannot inflate independent-workflow claims. These descriptive counts do not estimate production prevalence.

Adjudicate disagreements by reading frozen source; retain both original labels, the source citation and the final rationale. Where opaque helper/API semantics prevent resolution, retain Unknown. Do not remove difficult compositions or enrich the sample after labels to cross a threshold. Do not equate code agreement with semantic validity.

No operator time, errors, incident frequency, successful recovery, complete policy correctness, advantage over an equally informed manual/persisted rule, or acceptance verdict is measured. A separate real-history retrospective or human study remains necessary for those claims. Negative and inconclusive results will be retained.

## Provenance clarification during coding

Both workers inherited the parent session context, including prior paper examples. Full manuscript/project blinding is therefore not achieved. Neither worker is shown the other coder’s labels; separate source-grounded coding is the achievable separation. This clarification is recorded during coding, before aggregate results or adjudication, and does not alter the sample, coding schema, confidence rules or analysis. Reports must disclose the inherited context and project affiliation.
